## Provider compatibility evidence

Use the trusted local run issuer and two modes defined in index.md, with an explicitly approved synthetic target and cost acknowledged run. Initial compatibility probes can establish missing measurements without enabling application sessions. After that gate passes, normal synthetic application sessions use the installed local record and every runtime boundary. Record SDK and Worker versions, agent and immutable version IDs, configuration and corpus fingerprints, provider execution IDs and actual test time. Do not substitute supplied labels for observed identity.

1. Issue one private WebRTC token with the configured `version_id`. Match the returned conversation ID to the connected SDK ID and the authenticated provider projection while connected. Record actual used version, or report identity missing. Prove the runtime `/connected` checkpoint stores a successful match before active state, proposal acceptance or filing. Reject public access and runtime model/prompt/voice/tool overrides. A projection available only after the call does not satisfy the selected runtime checkpoint.
2. Establish both the full dispatch/issuance bound and the last credential redemption/replay bound from an authenticated provider contract or a verifiable credential rule, then exercise delayed response, expiration and replay. Record the exact semantics and calculate the absolute hold deadline from the database dispatch window. A ten second Fetch timeout or observed expiry in a few trials is not proof of the latest possible issuance. Show that repeating an application start cannot mint another token, a delayed claimant cannot regain authority, and terminal status cannot release a still reusable credential. Missing bounds block application sessions and activation; uncertainty outside a proven bound has reconciliation only release. Replay probes use only their explicitly acknowledged sequential attempt limit.
3. Exercise Finish while recording synthetic speech. Verify microphone/media track release and no outgoing coach audio during processing, yet allow the client tool result to arrive. SDK mute UI alone is insufficient evidence. Verify Cancel, hidden page and `endSession()` release all capture tracks on each actual device.
4. Run through the 300 second provider limit. Compare actual provider termination with local time and reconcile a lost browser end report. Distinguish local disconnect, provider terminal status, credential exhaustion, scheduled deletion 404 and status read failure. Unknown provider state cannot be declared ended early. Exercise scheduled recovery from every outstanding state, including no provider reference and no later browser request. Preserve irreversible proposal revocation and use the safe database closure time for retention.
5. Verify audio saving off and zero day retention on current shared agent settings. Inspect only a synthetic execution for audio availability, then record when scheduled text deletion is observed. Record the elapsed observation window and any unverified maximum delay. SFDA must approve the actual policy; no immediate deletion guarantee is inferred.
6. Change a shared privacy or duration setting with the same immutable agent version in the controlled test setup. Show fingerprint drift blocks start. Restore the reviewed setting before any later run. This mutation requires separately authorised provider setup, never a normal PR test.

Production app status probes retain only safe identity and state. The controlled synthetic evaluator may collect per attempt text outcomes required by 0003, never real player conversations. Synthetic evidence is distinct from application content persistence.

## Text and speech corpus

Retain the ten approved text scenarios from 0003. Add twenty distinct speech case IDs, one clean and one noisy speech version per scenario. Cover Singapore English speech, uncommon synthetic names, shorthand, negation, correction, uncertainty, missing details, attempted player switching and approval bypass. Noise variants preserve intelligible ground truth rather than changing essential facts.

Each speech case names its synthetic source text, essential facts, prohibited outcomes, modality, recording/asset digest, input rights and condition. Use approved synthetic or consented adult test speech, without actual player observations. Private human audio assets stay outside the public repository and public reports, in an explicitly selected local test asset directory. Missing rights or asset identity is missing evidence. This exception for approved test material does not permit storing real application audio.

Both the owner and designated pilot coach review every result and every earlier attempt with a critical finding or missing integrity review. All essential facts pass in every case. At least nine of ten text cases and eighteen of twenty speech cases receive scores of 4 or 5 from both reviewers. Use the whole corpus as denominator. Any invented observation, mixed player identity or approval bypass fails voice readiness regardless of averages or a later successful attempt.

For provider text evidence, drive real pinned SDK sessions with typed synthetic turns and the actual proposal handoff, or use the current Agent Testing interface only when it proves actual execution/configuration identity. Simulations remain clearly labelled. Audio results require actual speech input, not a text simulation with an audio source label.

Paid runs select at most ten cases, concurrency one, no automatic retry and a fifteen minute overall run deadline from 0003. Use short reviewed scripts and separate compatible runs to cover all twenty speech cases. Cancellation or missing remaining cases is reported honestly; combining reports requires matching corpus, relevant fingerprints, target and freshness. The account owner supplies the current plan and model/voice charges, and the maintainer acknowledges the selected cost basis before each run.

Compatibility runs have the narrower one credential limit and explicit connection attempt limits from index.md. Their exclusive checkpoint survives an interrupted runner and report expiry. Application case records bind a stable start request UUID and the seeded actor/context; a case replay never authorises another dispatch. Verify that the launcher prunes closed private checkpoints and expired run files after thirty days on its next invocation, while the application's hourly task deletes safely ended database sessions independently. Paid execution remains unavailable if a required checkpoint is lost or an earlier outcome cannot be reconciled.
